> 本文描述系统如何组装与取舍，不重复接口字段。所有端点、请求/响应与数据模型以 [API 契约](api-contract.md) 为唯一事实来源；本文不新增端点。

## 1. 目标与硬约束

- 面向 2–10 人家庭；一个部署实例的数据模型可容纳多个家庭，但容量与运维按单家庭规模设计。
- 服务部署在家中常开设备上，**没有公网 IP**；通过 VPS 上的 frp 反向代理（首选）或 Cloudflare Tunnel 暴露。
- Android 生产环境必须使用 HTTPS；本地局域网开发允许 HTTP。
- M1 固定为**单实例**：一个 Fastify 进程、一个 SQLite 文件、进程内维护设备长连接与指令去重；不引入 Redis、消息队列或容器编排。
- 坐标体系统一为高德 GCJ-02，客户端与服务端之间不做坐标转换。

## 3. 组件与职责

| 组件 | 运行位置 | 职责 | 明确不负责 |
|---|---|---|---|
| Android App | 家庭成员手机 | 前台服务定时上报、断网队列、立即定位执行、设备 WebSocket、地图与详情、权限/保活自检 | 家庭数据存储、跨设备查询 |
| Web 家庭端 | 浏览器 | 家庭地图、成员详情、历史轨迹、家庭/设备管理、管理操作 | 位置采集、后台任务 |
| Server（Fastify） | 家中设备容器 | REST API、鉴权、家庭范围推导、位置写入与查询、指令生命周期、设备 WebSocket、保留期清理 | 页面渲染、地图瓦片 |
| Caddy | 家中设备容器 | TLS 终结与自动续期、静态 Web 托管、反向代理、WebSocket Upgrade | 业务逻辑 |
| frpc / frps（或 cloudflared） | 家中设备 / VPS | 传输通道：把公网 80/443 转回家中 Caddy | 鉴权、内容检查 |
| Prisma + SQLite | 家中设备数据目录 | 数据持久化、迁移、索引 | 并发横向扩展 |
| 高德开放平台 | 第三方 | 地图瓦片、定位辅助、逆地理编码 | 业务数据存储 |
| 备份任务 | 家中设备宿主机 | 每日 SQLite 热备份、离机保存 | 在线服务 |

服务端模块（与原型书 6.3 一致）：`auth`、`families`、`devices`、`locations`、`locate`、`ws`、`retention`。M1 不包含部署者管理后台。

## 4. 部署拓扑

| 组件 | 监听 | 暴露范围 |
|---|---|---|
| frps（VPS） | `7000/tcp` 控制；`80/tcp`、`443/tcp` 转发 | 公网；7000 建议限制为家中出口 IP |
| Caddy（家中） | `80/443` | 家中局域网 + 经隧道 |
| Fastify（家中） | `3000` | 仅 Docker 内网（`expose`，不发布到宿主机） |
| SQLite（家中） | 文件 | 不监听端口 |

- **DNS**：frp 模式下 `域名 A → VPS 公网 IP`，且关闭 CDN 代理（Cloudflare 的灰云 / DNS only），否则 Caddy 无法完成 ACME 校验。
- **TLS 路径**：客户端到家中 Caddy 之间端到端 TLS；frps 仅做 TCP 转发，看不到明文。
- **静态 Web**：Web 构建产物挂载到 Caddy 的 `/srv/web`，与 API 同源，生产环境无需 CORS。
- **单机约束**：一个 Caddy + 一个 server 实例。设备在线状态与立即定位去重状态保存在进程内，**不得水平扩容**。
- **局域网**：开发期直连 `http://<家中设备 IP>:3000`（或 Vite `:5173`）；生产期手机统一使用公网 HTTPS 域名。若路由器不支持 NAT 回环，家中设备访问域名会失败，属网络设备限制而非应用缺陷。

## 5. 数据流

### 5.1 周期位置上报

```
Android 前台服务
  1) 高德定位回调 → 写入本地持久队列（断网、鉴权失败退避时不丢点）
  2) 按档位触发：省电 10 分钟 / 标准 3 分钟 / 高频 1 分钟（App 侧策略）
  3) 联网时取 1–100 个点批量发送：
       POST /api/locations
       Authorization: Bearer <deviceToken>
  4) 服务端：Token → Device → userId/familyId（客户端不传 familyId）
     写 Location → 更新 lastSeenAt → 若带 commandId 则完成对应指令
     返回 202 { accepted }
```

读取路径：

- Web 每 10 秒调用 `GET /api/families/me/latest` 刷新家庭地图（契约规定）。
- Android 前台进入/下拉刷新/立即定位结束后主动拉取；不在成员列表上使用浏览器 WebSocket。
- 历史轨迹：`GET /api/devices/:id/locations?from=&to=`，按 `recordedAt` 绘制折线。

设计要点：

- `recordedAt` 保留采样时间，`createdAt` 是入库时间；补传不会把旧位置伪装成新位置。
- 界面新鲜度以 `recordedAt` / `lastSeenAt` 推导，不依赖客户端本地时钟展示绝对时间。
- 批量上报在契约中没有幂等键，超时重试可能产生重复点（见 §10）。

### 5.2 立即定位（WebSocket 指令）

```
查看端（App/Web）        Server                          Android
   │ POST /api/devices/:id/locate                          │
   │─────────────────────►│                                │
   │                      │ 用户 JWT + 同家庭成员校验        │
   │                      │ 设备离线 → 409 DEVICE_OFFLINE   │
   │                      │ 30s 内有 pending → 复用并返回 200│
   │                      │ 新建 LocateCommand，deadline +30s│
   │ 202 {commandId, deadlineAt}                           │
   │◄─────────────────────│                                │
   │                      │ WS /ws {type:"locate",commandId}
   │                      │───────────────────────────────►│
   │                      │                                │ 单次高精度定位
   │                      │ POST /api/locations（设备 Token）
   │                      │ 携带 commandId                  │
   │                      │◄───────────────────────────────│
   │                      │ 写位置 → 指令 completed          │
   │ GET /api/commands/:id 轮询状态                         │
   │─────────────────────►│ pending → completed / timeout   │
   │ 刷新 latest（Web ≤10s 轮询，App 主动拉取）              │
```

- 超时 30 秒未回传 → 服务端定时任务标记 `timeout`，查看端在下次轮询时提示「对方离线或未开启定位」。
- 同一设备 30 秒内重复请求合并为一次，避免重复定位耗电。
- 契约定义了 `failed` 状态，但 M1 设备没有失败回执消息，实际失败只能表现为 `timeout`；`failed` 预留。
- 设备 WebSocket 仅用于指令下发与在线状态：连接建立 → `online=true`；断开或 90 秒无消息 → `online=false` 并更新 `lastSeenAt`。

### 5.3 设备注册与凭据生命周期

```
用户登录/注册 ──► userJwt（HS256，7 天）
     │
     └── POST /api/devices ──► 注册设备，返回一次性 deviceToken
                                 服务端仅存 SHA-256(token)
设备运行 ──► Authorization: Bearer <deviceToken>（仅位置上报与 /ws）
解绑/成员被移除 ──► 设备及其 token 立即失效，App 重新登录并注册新设备
```

- 用户 JWT 用于家庭、成员、设备管理与立即定位；设备 Token 只用于「上报位置」与「设备 WebSocket」，两者不可混用。
- Android 应把设备 Token 存入系统安全存储（Keystore 支撑的加密存储），不放日志、不放备份。
- M1 没有刷新令牌端点；JWT 7 天到期后重新登录。
- 解绑、移除成员、重置凭据的语义以契约为准。

### 5.4 刷新模型

原型书 F3 时序图暗示服务端向查看端推送位置；**M1 以实现为准，采用契约 §5 的 10 秒轮询**，浏览器不建立 WebSocket。对家庭地图而言 10 秒新鲜度足够，且避免了浏览器长连接鉴权、断线重连与多标签页连接管理。若后续对实时性有更高要求，再以契约变更的形式引入。

## 6. 信任边界与安全模型

### 6.1 边界

```
[Android / 浏览器]
   │ B1：TLS（公网 CA），Authorization 头携带凭据
   ▼
[VPS 转发面 / Cloudflare 边缘]
   │ B2：frp 隧道 TCP 透传（家中主动外连）或 Cloudflare 边缘终结 TLS
   ▼
[家中 Caddy：TLS 终点]
   │ B3：Docker 内网
   ▼
[Fastify] ── B4：文件权限 / 磁盘 ──► [SQLite]
   │
   └── B5：客户端直连高德（M1 服务端不调用高德接口）
```

| 边界 | 主要风险 | 控制 |
|---|---|---|
| B1 客户端 ↔ 公网入口 | 窃听、冒充服务端 | 公网 CA 证书、TLS 1.2+；M1 不做证书固定；凭据只放 Header，不放 URL |
| B2 公网入口 ↔ 家中 | VPS 被入侵后读取业务数据 | frp TCP 透传，TLS 在 Caddy 终结，VPS 只见密文与流量元数据；控制端口用 token + TLS |
| B3 宿主 ↔ 容器 | 误暴露管理端口 | server 仅 `expose` 3000，不映射宿主机；公网只开 Caddy 80/443；服务端只应信任来自 Caddy 的代理头（trustProxy 需在 server 侧启用） |
| B4 应用 ↔ 存储 | 磁盘被盗、备份泄露 | 数据目录权限、全盘加密（BitLocker/LUKS 等）、备份加密后离机保存 |
| B5 客户端 ↔ 高德 | 第三方获取位置 | 仅由客户端调用；Key 绑定包名/SHA1 或域名白名单；隐私政策披露；不向高德传家庭/账号标识 |

### 6.2 安全规则

- **家庭范围由服务端推导**：客户端不传 `familyId`；所有位置/设备查询先校验目标设备属于当前用户家庭。越权统一返回 `404`，不泄露资源是否存在。
- **账号安全**：密码使用 argon2；用户 JWT HS256 有效期 7 天；登录与加入家庭需要限流。
- **凭据分离**：用户 JWT（人）与设备 Token（设备）职责隔离；设备 Token 32 字节随机、只返回一次、数据库存 SHA-256，可单独吊销。
- **管理员操作**：重置邀请码、移除成员、清空家庭历史（待契约补齐，见 §10）仅管理员可做。
- **速率限制**：登录、邀请码加入、立即定位是重点；契约预留 `RATE_LIMITED` 错误码，服务端需落实（尤其 6 位邀请码空间仅 10^6）。
- **输入校验**：服务端 schema 校验坐标范围、批量条数（1–100）、历史查询 `limit` 上限（5000）、时间窗口；拒绝未知字段。
- **日志最小化**：不记录明文密码、设备 Token、完整位置序列；反向代理访问日志只含路径与 ID。
- **静态数据**：SQLite 文件本身不加密，依赖宿主磁盘加密与目录权限；备份必须加密后才能离机保存。
- **Android**：release 必须 HTTPS 且关闭 cleartext（当前骨架的 manifest 为本地调试全局开启，需要在 release 变体覆盖）；不做证书绕过/信任所有证书。
- **Web**：生产同源部署，关闭不必要的 CORS；JWT 存于浏览器存储，主要风险是 XSS，M1 通过不引入第三方脚本（高德除外）、严格转义降低风险；P1 再评估 HttpOnly Cookie 方案。
- **部署面**：VPS 只开 22/80/443/7000，SSH 用密钥；frps 7000 尽量限制来源；家中设备不直接暴露端口。

### 6.3 隐私与知情共享

- **知情**：首次启动的权限引导说明用途；共享期间有常驻通知；暂停开关立即生效，且暂停状态对家庭成员可见（契约 `sharingPaused`）。
- **最小化**：只采集契约定义的字段（经纬度、精度、速度、方向、电量、定位来源、采样时间）与设备基础信息；不采集通讯录、照片、麦克风、应用列表。
- **家庭内全可见**：M1 不提供成员级细粒度权限，同一家庭成员互相可见；这是产品明确的取舍。
- **保留**：保留期清理尚未在 server 落地（见 §10），M1 上线前需补上；备份文件必须采用不长于业务保留期的轮转，避免「已删除但备份还在」。
- **第三方**：高德会收到定位辅助/逆地理编码请求与地图瓦片请求；服务端不代理这些调用，但客户端仍会直连高德，隐私政策需披露。
- **部署者视角**：自建意味着服务器管理员理论上可接触数据库；这是「自家服务器」的信任前提，不是家庭管理员权限的一部分。

## 7. 技术决策

| 决策 | 选择 | 理由 | 代价与边界 |
|---|---|---|---|
| Android 技术栈 | Kotlin + Compose，原生前台服务 | 后台定位、前台服务、系统权限与国产 ROM 保活设置强依赖平台能力；跨平台框架在后台存活上不可控 | 仅支持 Android；需要自行处理 ROM 差异 |
| 地图与定位 | 高德（Android SDK + JS API） | 国内可用性与 POI 质量；两端同为 GCJ-02，无坐标转换；逆地理编码成熟 | 供应商锁定；需处理隐私合规与 Key 绑定 |
| Web 框架 | Vue 3 + Vite SPA | 家庭端是小规模交互应用，无需 SSR/SEO；开发迭代快，与 REST 契约契合 | 浏览器内 Token 有 XSS 风险；首屏需加载 JS |
| 服务端框架 | Fastify | 轻量、schema 校验内建、插件体系清晰，配合 `@fastify/websocket` 覆盖 REST 与设备长连接 | 生态小于 Express；团队需熟悉插件约定 |
| 持久化 | Prisma + SQLite | 单机零运维、单文件易备份；家庭规模写入压力极低 | 单写者、无水平扩展；备份需注意 WAL/journal；大量数据清理需要专用任务与 VACUUM |
| 设备指令通道 | 设备主动外连的 WebSocket | 家中无公网 IP，设备出站连接最稳；指令即时；不依赖 FCM/推送（国内不可靠） | 需心跳、重连退避与在线状态维护；进程重启后状态需重建 |
| 查看端实时性 | 10 秒轮询（浏览器） | 契约已定义；实现简单、无浏览器长连接状态；家庭规模流量可忽略 | 最坏 10 秒延迟；「立即定位」结果感知慢于此 |
| 鉴权模型 | 用户 JWT + 每设备 Token | 人与设备生命周期分离；设备可单独吊销；Token 哈希存储降低库泄露影响 | 重装 App 需重新注册设备；无刷新令牌，7 天后需重登 |
| 部署形态 | Docker Compose + Caddy + frp | 单机声明式部署、回滚简单；Caddy 自动 HTTPS 与 WebSocket 透传 | 无高可用；升级需人工；Windows 宿主的文件 I/O 弱于 Linux |
| 公网入口 | frp + VPS（首选），Cloudflare Tunnel（备选） | frp 配近端 VPS 延迟低且 TLS 端到端；Cloudflare 无需公网端口但有绕行延迟 | frp 需维护 VPS 与 80/443；Cloudflare 使边缘可见明文且中国大陆线路不稳定 |
| 静态资源 | Caddy 直接托管 `web/dist` | 服务端不承担静态资源分发，Web 与 API 同源 | 多一步构建/复制；构建缺失时首页 404 但 API 正常 |
| 逆地理编码 | 客户端调用高德（最新位置） | 无需服务端高德 Key 与出网调用；地址不进入数据库，减少敏感数据留存 | 历史点默认不批量反查地址；离线时地址可能缺失 |

**容量估算**：标准档 3 分钟/点 → 每人每天 480 点；10 人约 4,800 点/天，90 天约 43 万行。高频档 1 分钟/点 → 10 人 90 天约 130 万行。单文件 SQLite 在家庭规模下完全够用；Web 端每 10 秒轮询，每个查看者每天约 8,640 次请求，对家中设备无压力。

## 9. 失败模式与运维

### 9.1 失败模式

| 场景 | 检测 | 系统行为 | 用户可见 / 兜底 |
|---|---|---|---|
| 手机断网/弱网 | 上报失败 | App 保留本地队列，退避重试；WS 断开后重连 | 顶部连接中断提示；恢复后批量补传 |
| App 被系统杀死 | WS 断开超过 90 秒 | 服务端置 `online=false`；前台服务尝试重启 | 家人端显示离线与最后在线；需权限自检/保活设置 |
| 无 GPS/室内/系统定位关闭 | 高德回调错误或精度极差 | 不伪造坐标；有网络定位则上报大精度点 | 大精度圈与「精度较低」；立即定位可能超时 |
| 定位权限被撤销 | 高德错误码/权限检查 | 停止上报，App 提示修复 | 家人端离线；权限自检入口 |
| 服务端重启 | 容器退出/重启 | 所有 WS 断开，设备退避重连；启动时将设备置 offline | Web 短暂报错后恢复；pending 指令到期转 timeout |
| 隧道/VPS 故障 | 客户端请求失败、frpc 日志 | Android 继续缓存位置；Web 显示连接异常 | 恢复后补传；需人工重启 frpc/frps |
| 家中设备断电/磁盘故障 | 服务不可达 | 无在线服务 | 从离机备份恢复；这是自建方案的单点风险 |
| SQLite 锁/磁盘满 | 写入 5xx/日志 | 请求失败，设备重试 | 清理磁盘或修复数据目录权限；可能产生重复重试点 |
| 设备时间异常 | `recordedAt` 偏差 | 按客户端时间入库会污染轨迹 | 依赖 NTP；建议服务端限制异常未来时间（需契约/服务端确认） |
| 证书续期失败 | Caddy 日志、浏览器告警 | 到期后 Android/浏览器拒绝连接 | 检查 80/443 与 ACME 日志，立即处理 |
| 设备解绑/Token 失效 | 401 | 停止上报与 WS；需重新登录注册 | App 引导重新绑定 |
| 高德服务异常/配额 | 地图空白、定位错误 | 上报与查看受影响，业务数据不丢 | 检查 Key 配额与控制台；地图不可用时仍保留历史数据 |

### 9.2 运维要点

- **备份**：每日热备 SQLite（`.backup` 或停服复制），加密后离机保存；每季度演练恢复。详见 [部署指南](setup.md)。
- **日志**：`docker compose logs` 为唯一日志源；容器日志轮转（compose 已配置），不记录敏感字段。
- **升级**：先备份 → 构建新镜像 → 执行 server 提供的数据库结构同步（当前 `server/package.json` 为 `db:push`，生产以镜像启动流程为准）→ 重启 → 验证登录、上报、定位、WS；数据库结构变更只向前，回滚优先恢复备份。
- **保留期**：M1 尚无自动清理任务（见 §10），上线前需补齐每日清理；大批删除后按需 `VACUUM`；磁盘水位人工巡检（建议低于 80%）。
- **时钟**：家中设备与手机开启 NTP；接口时间统一 ISO 8601 UTC，展示按客户端时区。
- **证书**：Caddy 自动续期；监控 `caddy` 日志中的 ACME 失败与证书到期时间。
- **入口**：frps 7000 端口尽量限制来源；VPS 只开必要端口；密钥登录；frp token 定期轮换。
- **单实例纪律**：不要 `docker compose up --scale server=2`；不要同时运行开发实例与生产实例指向同一 SQLite 文件。
- **恢复目标**：M1 接受数小时级 RPO（按备份频率）与小时级 RTO，不做热备切换。

## 10. 契约缺口与待确认

以下问题超出本文范围，需在 [API 契约](api-contract.md) 或产品侧确认后再实现，避免三端各自发明：

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 原型 W06 的「按家庭设置保留天数」在 Prisma 模型中无字段，server 也无对应配置 | M1 暂无保留期清理入口 | 契约增加 `Family.retentionDays` 与更新端点；server 先补全局保留配置 |
| 2 | 权限表允许管理员「清空家庭历史位置」，但契约无对应端点 | Web 设置页无法实现该 P0 操作 | 契约补充管理端点并注明级联范围 |
| 3 | `POST /api/locations` 无幂等键 | 超时重试可能写入重复轨迹点 | 契约增加客户端批次 ID，或服务端按 `(deviceId, recordedAt)` 去重 |
| 4 | 原型 F3 画的是服务端向查看端推送位置，契约定义 Web 轮询 | 实现口径不一致 | 以契约为准（本文 §5.4）；产品确认 10 秒可接受 |
| 5 | 6 位邀请码的加入尝试速率限制未量化 | 可被暴力枚举（空间 10^6） | 服务端实现失败计数/限流并返回 `RATE_LIMITED` |
| 6 | 原型按 10 人家庭设计，契约未定义上限 | 服务端是否拒绝第 11 人未定 | 产品确认后写入契约并在加入流程提示 |
| 7 | 契约无地址字段，原型多处展示地址 | 历史轨迹的地址无法从服务端获得 | M1 客户端对最新位置逆地理编码；历史地址不做或按需反查 |
| 8 | `LocateCommand.failed` 在 M1 无写入路径 | 前端可能实现无法触发的状态 | 明确 M1 只用 pending/completed/timeout |
| 9 | Web 将 JWT 存于浏览器存储 | XSS 可窃取 7 天会话 | M1 接受（无第三方脚本）；P1 评估 HttpOnly Cookie + CSRF |
| 10 | server 未启用 Fastify trustProxy | 经 Caddy 后所有请求的 IP 都是代理 IP，限流按全局计数 | server 显式信任来自 Caddy 的代理头；部署层不直接暴露 3000 |

**需要用户输入才能定稿的事项**：

- 生产域名与 DNS 控制权（影响 Caddy 证书、AMap JS 域名白名单）。
- 是否有可用 VPS（地区/带宽影响 frp 方案与延迟），否则改用 Cloudflare Tunnel。
- 家人手机品牌与系统版本（影响保活引导默认项与真机验证计划）。
- 默认上报档位、家庭人数上限、历史保留天数（原型书 §13）。

以上部署与环境配置步骤见 [部署指南](setup.md)。
